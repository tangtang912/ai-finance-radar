# 09 号：HITL 审核闸（三大亮点②）

## 功能说明

在 07 号主图上加一道**人工审核闸**：Agent 每次要行动前先暂停，等真人**批准 / 驳回 / 退出**。

## 为什么需要 HITL？

| 场景 | 没有 HITL | 有 HITL |
| :--- | :--- | :--- |
| Agent 想调错工具 | 直接执行，浪费 token | 人工拦下，直接驳回 |
| Agent 推理方向偏了 | 一路跑到底，输出错误 | 人工给意见，让它重新想 |
| 敏感操作（如生成结论） | 直接输出 | 人工确认后再放行 |
| 调试 Agent | 只能看日志 | 每步可干预 |

**一句话**：Agent 再聪明也会犯错，关键节点需要"人来把关"。

## 核心知识点

| 知识点 | 说明 |
| :--- | :--- |
| **`MemorySaver`** | 检查点：把图状态存内存，中断后能恢复 |
| **`interrupt_before=["agent"]`** | 中断开关：进 agent 节点前自动暂停 |
| **`thread_id`** | 会话 ID：检查点按它分开存，多会话隔离 |
| **`app.get_state(config)`** | 查看当前状态（闸前的最后一条消息） |
| **`Command(resume=True)`** | 放行：从闸前继续执行 |
| **`app.update_state(config, ...)`** | 人工写入消息（如驳回意见） |
| **`is_finished()`** | 判断是否结束（最后一条 AIMessage 无 tool_calls） |
