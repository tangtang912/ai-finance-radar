# 第 1 周任务 3：命令行问答 + 溯源

## 功能说明

基于任务 2 的 FAISS 向量库，实现**带页码溯源的命令行问答**。

## 核心流程
用户提问
↓ db.similarity_search(query, k=8)
8 条最相关文本块（含文件名 + 页码）
↓ 拼提示词（含 4 条铁律）
Prompt（规则 + 摘录 + 问题）
↓ llm.invoke()
答案（含 [content_i] 溯源标注）

## 核心知识点

| 知识点 | 说明 |
| :--- | :--- |
| `FAISS.load_local()` | 加载落盘的索引 |
| `allow_dangerous_deserialization=True` | 允许反序列化（FAISS 需要，仅本地可信场景使用） |
| `ChatOpenAI` + DashScope 兼容模式 | 用 OpenAI SDK 调通义千问 |
| `similarity_search(query, k=8)` | 语义检索 Top-K |
| **提示词工程** | 4 条铁律约束模型输出 |

## ⭐ 提示词的 4 条铁律（本任务的核心）

| 规则 | 作用 |
| :--- | :--- |
| **1. 不许编造** | 摘录里没有的直说"没找到"，防止幻觉 |
| **2. 口径差异提示** | 没有精确口径时给最接近的 + 说明差异 |
| **3. 数量级检查** | 千元/百万元换算成亿元，防止看错零 |
| **4. 必须溯源** | 答案要注明出自哪条摘录 |

**为什么这 4 条重要？** 财报数字动辄上亿，一个"看错零"就可能差 10 倍。规则 3 强制模型先换算再检查，是金融场景的必备防护。
